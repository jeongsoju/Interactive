## 메모 (2단계에서 정한 것)

- 앱의 시간 판단은 `VehicleState.nowMillis`만 쓴다(기기 시계 직접 사용 금지). 시작 시각만 `RecordingEngine`에서 기기 시계로 정한다.
- (7단계에서 해결) 샘플 동 코드는 실제 행정동 코드로 바꿨다.
- 모드를 바꿀 때 "샘플 데이터 초기화" 물음은 지금은 샘플을 다시 읽는 것까지만 한다. 기기 안 저장은 4단계에서 붙인다.
- 시연·직접 조작 모드는 실제 기어가 P라서 시스템이 화면을 가리지 않는다. 10단계에서 가짜 기어가 D/R이면 앱이 직접 "주행 중" 가림 화면을 띄운다.
- 직접 조작 패널은 가로 화면에서 2열로 배치해 데이터 초기화 버튼까지 스크롤 없이 보이게 한다(3단계 작업 중 같이).
- 샘플 JSON 읽기 테스트는 기기에서 도는 테스트다(`./gradlew :automotive:connectedDebugAndroidTest`, 에뮬레이터 필요).

## 메모 (3단계에서 정한 것)

- N(중립) 무시, 날짜 바뀜은 기기 시간대 기준 → spec.md "결정됨" 표에 적었다.
- 여행 기록(`TripRecorder`)은 메모리에만 둔다. 저장은 4단계, 동 코드는 7단계(지금은 정차의 dongCode가 null), 경로 점(1분 간격)은 4단계에서 붙인다.
- 체류 확정(`StayConfirmed`)과 정차 끝 이벤트는 영토 갱신(8단계)과 P 카드(10단계)가 받아 쓴다.
- 60배 재생은 화면 갱신이 0.25초(가상 15초) 단위라 정차 시간이 1분쯤 작게 보일 수 있다.
- 화면을 만들 때(9~14단계)는 docs/design/mockups 이미지를 보고 배치를 맞추고, 색·효과는 10-1단계에서 입힌다. 디자인 기준은 docs/design/README.md.

## 메모 (4단계에서 정한 것)

- 저장은 Room(`automotive/.../db/AppDatabase.kt`): 여행·정차·경로 점 3개 표. 기록 규칙(`TripRecorder`)은 저장을 모르고, 화면 담당(`RecordingEngine`)이 일어난 일(TripEvent)을 받아 순서대로 저장한다.
- 앱을 켜면 저장분을 불러와 `TripRecorder.restore`로 이어간다. '데이터 초기화'와 모드 바꿀 때의 초기화는 저장된 기록도 지운다. 10분 미만 '잠깐 멈춤'은 저장하지 않는다.
- 경로 점: 여행 시작 때 1점, 이후 달리는 중 1분마다(정차 중·위치 없음 제외).
- 알려진 한계: 다시 켠 직후 체류 확정(StayConfirmed)이 한 번 더 나올 수 있다(영토 점수 계산은 8단계에서 같은 정차를 두 번 세지 않게 한다). 직접 조작 모드는 앱을 켜면 기어가 P부터 시작해서, 저장된 여행에 새 정차가 하나 더 생긴다.
- 확인: 직접 조작 모드에서 D→P→+20분→D 후 앱을 강제 종료·재시작했을 때 여행 1개·체류 20분이 그대로 보였다.

## 메모 (5단계에서 정한 것)

- 기록 장치는 화면(Activity)이 아니라 앱 프로세스가 갖는다: `InteractiveApp.engine`(= `RecordingEngine`, 예전 VehicleViewModel). 화면은 이것을 가져다 보여주기만 한다.
- `RecordingService`(포그라운드 서비스)가 프로세스를 살려 둔다. 앱을 열 때 시작되고, 상단에 "여행을 기록하고 있어요" 알림이 뜬다. 서비스 종류는 `specialUse`(권한 `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`). 6단계에서 실제 위치를 읽을 때 종류를 `location`으로 바꿀지 본다.
- 시연 모드 60배로 재생하다가 뒤로 가기로 화면을 나갔다 20초 뒤 돌아오니 앱 시각이 20분 흘렀고 거리·정차 기록도 이어져 있었다(서비스 foreground 상태는 dumpsys로 확인).
- 설명회 질문(spec.md): 포그라운드 서비스 허용 여부. 허용 안 되면 시연 외 실제 차에서는 기록이 끊길 수 있다.

## 메모 (6단계에서 정한 것)

- `RealVehicleDataSource`(automotive 모듈): 기어=`CarPropertyManager` GEAR_SELECTION, 주행 규제=`CarUxRestrictionsManager`, 누적거리·좌석=Pleos Vehicle SDK 2.3.2(Odometer·Seat), 위치=`LocationManager`(GPS). 모드 선택창에 "실제 차 모드"를 추가했다. API 이름은 `docs/pleos/vehicle-sdk-api-notes.md`.
- 에뮬레이터에서 확인됨: 기어·주행 규제·누적거리·좌석 5곳 연결, `adb emu geo fix`로 넣은 위치가 화면에 표시됨. 기어 값 바꾸기는 adb로 안 되고(사용자 빌드 제한) Virtual Console로만 가능.
- Virtual Console 확인 완료: ① 기어 P↔D가 앱에 반영되고 여행·정차가 기록됨 ② Motion의 Odometer에 9277을 넣자 앱에 `9277.0 km`로 표시 → 누적거리 단위는 km(변환 불필요). 에뮬레이터에서 ACCEL로는 누적거리가 늘지 않아 값을 직접 넣어야 한다.
- 권한: `CAR_POWERTRAIN`(기어), `CAR_DRIVE`·`CAR_SEATS`(Pleos), `ACCESS_FINE_LOCATION`(실행 중 허용창). 실제 차에서 `CAR_POWERTRAIN`이 서드파티에 허용되는지는 설명회 질문(spec.md).
- 실제 차 모드에서 처음 상태는 P·0km로 시작하고 값이 오면 갱신된다. D가 odometer보다 먼저 오면 여행 시작 거리가 0으로 잡힐 수 있어, 7단계 이후 필요하면 다듬는다.

## 메모 (7단계에서 정한 것)

- 경계 데이터는 `assets/dongs_gangneung.json`, 읽기는 `DongBoundaryLoader`, 위치→동은 공용 모듈의 `DongLocator`(`find`/`codeAt`/`byCode`). 출처·가공 방법은 [data-sources.md](data-sources.md). 출처 표시는 13단계 설정 탭에 넣는다.
- 동 코드는 행정안전부 10자리(`adm_cd2`). 샘플 데이터(`sample_data.json`)의 임시 코드(GN01~)를 실제 코드로 바꿨고, 동 목록은 코드만 적고 이름·중심 좌표는 경계 데이터에서 가져온다. 예전 "교동·포남동"은 실제 행정동 이름인 "교1동·포남1동"으로 바뀌었다.
- `TripRecorder`가 정차를 시작할 때 `dongCodeAt`으로 동 코드를 채운다(경계 밖이면 null → "경계 밖", 위치가 없으면 "위치 없음"). `RecordingEngine`이 `dongLocator`를 들고 있다.
- 검증: 단위 테스트(`DongLocatorTest`, 모양·여러 조각·경계 밖), 기기 테스트(`DongBoundaryLoaderTest`: 21개 동 읽기, 동마다 대표 지점이 자기 동 안, 경포대·주문진항 위치, 서울·삼척은 null), 에뮬레이터 화면에서 동 이름 표시 확인.
- 고친 버그: 앱 시작 때 샘플을 읽는 코드가 경계 데이터보다 먼저 실행돼 서비스가 죽던 문제(속성 선언 순서). 기기에서 실행해 보고 발견했다.

## 메모 (8단계에서 정한 것)

- 점수 계산은 공용 모듈의 `TerritoryScorer`(순수 함수, 테스트 10개): 내 점수 = 최근 30일 체류 분(1회 최대 4시간) + 방문한 날 수 × 30, 우리 집 동네 제외. 주인 = 최고점, 동점이면 현재 주인 유지, 모두 0이면 없음. 내 id는 `"me"`(`TerritoryScorer.MY_ID`).
- 친구(민지·준호) 점수는 `sample_data.json`의 영토 값을 그대로 쓴다(가짜 데이터, 계산하지 않음). 내 점수는 샘플 지난 여행의 정차 + 지금 기록된 정차로 계산한다.
- `RecordingEngine`이 체류 확정(`StayConfirmed`)과 체류로 끝난 정차 때마다 영토를 다시 계산하고, 주인이 바뀐 동은 `territoryChanges`(최근 5개)에 남긴다. 10단계 P 카드가 이것을 읽어 "땅을 차지했어요"를 띄운다. 영토는 저장하지 않고 정차 기록에서 매번 다시 계산한다.
- `homeDongCode`는 지금 null로 넘긴다. 13단계 설정 탭에서 '우리 집 동네'를 받으면 연결한다.
- 확인: 시연 모드 60배로 교1동에서 10분을 채우자 "교1동 주인 없음 → 내 땅(40점)", 송정동은 내 점수 75→130(준호 300이라 주인 유지).
- 알려진 한계: "차지하는 중"(10분 채우기 전 상태)은 아직 계산하지 않는다. 지도·카드를 만드는 9~10단계에서 정차 진행 시간으로 화면이 판단한다.

## 메모 (9단계에서 정한 것)

- 화면 뼈대 `AppRoot`: 지도가 전체를 채우고 탭 막대(알약 모양)가 아래 가운데에 뜬다. 지금 탭은 "지도"와 "기록(임시 확인 화면)" 둘뿐이다. 11~14단계에서 기록·영토·설정을 채우고 4개로 묶는다.
- 지도 탭 `MapScreen`: OpenFreeMap liberty 스타일 위에 동 경계를 GeoJSON으로 칠한다(내 땅 파랑, 친구 땅 주황, 주인 없음 회색 점선; 색은 디자인 표 라이트 값). 차 위치는 파란 점. 영토가 바뀌면 색이 다시 칠해진다. 동을 누르면 상세가 열리는 것은 아직 없다(디자인 04·05는 후순위).
- 강릉 지도 미리 받기 완료: 지도 파일을 `assets/mbgl-offline.db`에 넣어 첫 실행 때 복사한다. 네트워크를 끈 에뮬레이터(비행기 모드)에서 지도·동 색·확대(줌 약 12)까지 정상 확인. 출처·조건·다시 받는 방법은 [data-sources.md](data-sources.md).
- 새로 늘어난 것: 권한 `INTERNET`, 라이브러리 MapLibre 13.7.1과 OkHttp 4.12.0(MapLibre가 이미 쓰는 같은 라이브러리를 요청 수·User-Agent를 정하려고 직접 선언).
- 디버그 APK가 약 102MB다(MapLibre가 CPU 종류 4개용 라이브러리를 모두 포함). 15단계 제출용 빌드에서 CPU 종류를 줄여 크기를 확인한다.
- 알려진 한계: 지도 색은 라이트만, 글래스 효과·다크 모드는 10-1단계. 지도 시작 위치·확대는 강릉 중심(줌 11) 고정이고 차를 따라가지 않는다.

## 메모 (10단계에서 정한 것)

- 카드 고르기는 공용 모듈 `PCardPicker`(순수 함수, 테스트 9개): 영토 변화 → 처음 온 곳 → 여행 요약 순으로 하나. 한국어 조사(을/를, 이/가)와 금액 표기(1만 9천 원)도 같은 패키지(`card/Text.kt`).
- "영토 변화 카드" 조건: 주차한 동이 **친구 땅**이고, 여기서 10분 머물면 내 점수가 친구를 **넘을 때**. 이미 내가 와 본 동이면 "되찾을 수 있어요", 아니면 "차지할 수 있어요". 체류 10분이 확정돼 정말 내 땅이 되면 카드 내용이 **한 번만** "○○동이 내 땅이 됐어요 / ○○님에게서 차지했어요."로 바뀐다(`PCardPicker.confirmed`). 친구가 내 땅을 빼앗는 경우는 친구가 가짜 데이터라 아직 없다.
- 카드는 `RecordingEngine.pCard`가 들고 있다: 정차 시작(`StopStarted`)에서 만들고, 정차 끝(`StopEnded`, 즉 D·R)에서 지운다. 화면(`PCardOverlay`)은 기어가 P일 때만, 그리고 실제 차 모드에서 주행 규제가 꺼져 있을 때만 그린다. "닫기"는 카드를 지우고, "영토 보기"는 지도를 그 동으로 옮긴다(`focusDong`).
- 화면: 가로형은 왼쪽 패널에 카드 + "이번 여행"(거리·운전 시간·들른 곳·연료비), 세로형은 탭 막대 위 아래 시트에 카드만(코드는 있으나 세로형 화면은 14단계에서 확인).
- 연료비는 기본 연비(`AppConfig.DEFAULT_FUEL_EFFICIENCY_KM_PER_LITER = 12.0`, 임시)와 기본 유가로 추정하고 "(추정)"을 붙인다. 13단계에서 차종별 공인연비로 바꾼다.
- 시연용 샘플 변경: 송정동 준호 점수 300 → 100 (시연 경로에서 영토 변화 카드와 "내 땅이 됐어요"로 바뀌는 장면이 나오게).
- **명세서와 디자인이 다른 점(질문)**: spec F3은 "카드 내용이 바뀌는 유일한 예외는 영토 변화 카드"라고 하지만, 디자인 README는 "처음 온 곳" 카드에 머문 시간 진행 막대(4분 / 10분)를 둔다. 지금은 디자인대로 막대가 시간에 맞춰 차오르게 했다(애니메이션은 없음). 10분이 지나도 처음 온 곳 카드의 문구는 그대로다.
- 확인한 것: 시연 60배에서 초당동(와 본 곳)=여행 요약 카드, 주행 중=카드 숨김, 교1동(처음)=처음 와본 곳 + 진행 막대 + 이번 여행, 송정동=10분 뒤 "내 땅이 됐어요"로 변경 + 지도 색 파랑. 영토 변화 카드의 처음 문구("되찾을 수 있어요")는 단위 테스트로 확인했고 화면 캡처는 못 찍었다.

## 메모 (10-1단계에서 정한 것)

- 색은 `ui/theme/AppColors.kt`의 토큰(라이트·다크) 한 곳에 모았다. 화면은 `LocalAppColors`만 쓴다(색을 직접 적지 않는다). 다크는 시스템 낮·밤 설정을 따른다. Material 색도 이 토큰에서 만든다(`Theme.kt`).
- 글래스 카드는 `ui/Glass.kt`(반투명 + 테두리 + 그림자, 모서리 44, 칩은 알약). **뒤 흐림(블러)은 넣지 않았다**(라이브러리 추가 없음). 대신 시안(58~66%)보다 진하게(93%) 해서 글자가 비쳐 보이지 않게 했다. 블러가 꼭 필요하다고 판단되면 그때 이유를 말하고 승인받는다.
- 화면 구성(`AppRoot`): 위 왼쪽 기어 칩("P 주차 중 · 강릉 ○○동"), 위 오른쪽 "내 영토 N곳" 칩, 오른쪽 아래 범례(가로형만), 아래 가운데 알약 탭 막대(선 아이콘 + 글자, `ui/TabIcons.kt`). 탭은 지금 지도·기록 둘뿐(영토·설정은 12·13단계).
- 지도: 라이트는 positron, 다크는 dark 스타일 + 땅·바다·영토 선·채움을 디자인 표 색으로 맞춤, 차 위치 점에 퍼지는 연한 원 추가. 지도 파일(`mbgl-offline.db`)은 두 스타일로 다시 받아 교체(15.5MB, 타일 재사용). 비행기 모드에서 라이트·다크 모두 확인.
- 확인 캡처: `docs/screenshots/10-1-*.png`(가로 라이트 "송정동을 되찾을 수 있어요", 가로 다크 "송정동이 내 땅이 됐어요"). 세로형·다크 시안과의 나란히 비교는 14단계에서 형태별로 한 번 더 한다.
- 시안과 다른 점: 카드 제목이 길면 글자 단위로 줄이 바뀐다("있어/요"). 글꼴은 시스템 한글 글꼴(Asta Sans 없음). 선택된 동 강조·동 상세 화면(시안 04·05)은 후순위라 만들지 않았다.

## 메모 (11단계에서 정한 것)

- 기록 탭(`RecordsPanel`): 여행 목록(날짜별 묶음, 두 줄 요약: 시간 / 거리·연료비(추정)·들른 곳 수, 진행 중 칩)과 여행 상세(← 목록, 날짜, 요약, 들른 곳 목록: 번호·동 이름·시간·체류 분·탑승 인원·내 땅 칩). 가로형은 왼쪽 패널, 세로형은 아래 시트(세로형 화면은 14단계에서 확인).
- 데이터: 공용 모듈 `TripEntries.build`가 샘플 지난 여행과 지금까지 기록한 여행을 합쳐 최신순으로 만든다(`TripEntry.key`는 `sample-1`/`rec-1`처럼 구분: 두 곳의 id가 겹쳐서). 테스트 3개.
- 지도는 이제 기록 탭에서도 뒤에 깔린다(`MapScreen(vm, highlight, wide)`). 고른 여행의 경로(흰 바탕선 + 파란 선)와 정차 지점(파란 점)을 그리고, 고를 때 한 번 카메라를 경로에 맞춘다(패널에 가리지 않게 가로형은 왼쪽 여백). 경로 점이 2개 미만인 지난 샘플 여행은 정차 위치를 시간순으로 이은 선을 쓴다(그 선은 실제 도로가 아니라 직선).
- "차지한 동"은 따로 기록하지 않고, 정차한 동이 지금 내 땅이면 "내 땅" 칩으로 보여 준다(여행 중 변화 이력은 저장하지 않음).
- 임시 "개발" 탭을 추가했다: 모드 바꾸기·직접 조작 패널·재생 속도(기존 임시 화면). 13단계 설정 탭으로 옮기면 이 탭은 없앤다.
- 알려진 한계: 연료비는 임시 연비(12km/L)로 추정(13단계에서 차종 반영). 목록이 길어도 한 번에 모두 그린다(여행이 수십 개가 되면 느려질 수 있어 12단계 이후 필요하면 나눠 그린다).
- 확인 캡처: `docs/screenshots/11-records-list.png`, `11-records-detail.png`.

## 메모 (12단계에서 정한 것)

- 영토 탭(`TerritoryPanel`): "내 영토 N곳" 제목, 빼앗길 수 있는 땅 개수 안내, 내 땅 목록(내 점수 · 가장 센 경쟁자 점수, 위험하면 "빼앗길 수 있어요" 칩), 친구 순위(나·민지·준호의 땅 개수와 막대). 땅을 누르면 지도가 그 동으로 간다(`showDongOnMap` 재사용).
- 계산은 공용 모듈 `TerritoryOverview`(순수 함수, 테스트 5개). 위험 기준은 **가장 센 경쟁자 점수 ≥ 내 점수의 80%**(`AppConfig.AT_RISK_SCORE_RATIO`, spec.md "결정됨" 표에 적음. 명세서에 숫자가 없어 내가 정한 값이니 바꾸고 싶으면 알려 달라).
- 기록 탭과 영토 탭이 같은 패널 틀을 쓰도록 `ui/SidePanel.kt`로 뽑았다(가로형 왼쪽 패널, 세로형 아래 시트).
- 시연용 샘플 변경: 송정동 준호 점수 100 → 110. 시연 경로에서 송정동을 차지한 뒤 130 대 110이라 "빼앗길 수 있어요"가 나온다.
- 탭이 4개가 됐다(지도·기록·영토·개발). 13단계 설정 탭이 개발 탭을 대신한다.
- 확인: 시연 60배로 돌린 뒤 영토 탭에서 내 땅 목록·위험 표시·친구 순위, 땅을 눌러 지도 이동까지 확인(`docs/screenshots/12-territory-tab.png`). 세로형 화면은 14단계.
- 알려진 한계: 친구가 가짜 데이터라 "친구에게 빼앗김"은 일어나지 않는다. 위험 표시는 있지만 알림은 보내지 않는다.
